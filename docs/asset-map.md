# 资产图谱与攻击面

主机纳管后，平台自动回答两个问题：

- **运维**：这台机器是干什么的、有多重要、依赖谁、被谁依赖（资产图谱）
- **安全**：哪些服务暴露在哪一层、谁在访问、哪些机器还没纳管（攻击面）；暴露的服务有没有已知漏洞
  （服务进程所属的包对上 [软件漏洞](vulns.md)，攻击面表里标出漏洞数与最高分）

事实全部来自确定性采集，AI 只做解读：AI 标的角色和重要程度可以人工修改并锁定，
暴露面与盲区不经过模型，按规则计算。

实现位置：agent `collector/inventory*.rs`、`collector/cloud.rs`；server `internal/assetmap`、
`internal/api/assetmap.go`；前端「资产 → 资产图谱 / 攻击面」与资产详情页的「资产画像」。

## 数据来源

| 事实 | 来源 | 说明 |
|---|---|---|
| 监听端口与属主进程 | agent 设备清单（class 5001） | Linux 读 `/proc/net/{tcp,tcp6,udp,udp6}`，Windows 读 IP Helper 监听表；每 60 秒比对，变化或满 6 小时才上报 |
| 云环境 | agent 设备清单（class 5001） | 启动时探测一次 AWS / Azure / GCP / 阿里云 / 腾讯云元数据服务；拿不准就不报 |
| 系统显示名（发行版+版本） | agent 设备清单（class 5001） | Linux 读 os-release 的 `PRETTY_NAME`，Windows 读注册表；物化到资产 `os_display`，覆盖文档导入时声明的值 |
| 依赖边 | 网络事件（class 4001） | agent 出站连接（Linux 需 eBPF 构建，Windows 走 ETW）与 sensor 会话 |
| 见过的程序 | UEBA 基线 | 只给 AI 标注做参考 |

server 侧由集群单活的 `assetmap` 任务消费已落库的 4001 / 5001 / 5020（软件清单）事件，
把清单物化到资产上、把连接聚合成依赖边（`asset_links`）。新安装默认使用持久待办：
原始事件与 `assetmap_queue` 在同一事务写入，每批最多领取 1000 条，图谱更新与待办删除也在同一事务提交。
失败回滚后可以重试，重复投递已入库的事件不会重新计数。消费按入库待办顺序推进，不以事件时间过滤，
补传的旧事件也能进入图谱；清单按时间保留最新快照，连接的首次、最近时间取最小值和最大值。
`settings.assetmap.cursor` 保留已处理事件的时间进度，但在待办模式下不再决定哪些事件会被消费。
首次启用回补最近 7 天的连接；30 天没再出现的边自动删除。

### 已有集群升级到持久待办

已有 `assetmap.cursor` 的数据库升级后先保持 `legacy` 模式，允许多节点滚动升级。
必须先确认**所有写入节点与图谱工作者均运行支持持久待办的版本**，再在数据库执行：

```sql
UPDATE settings SET value='"requested"'::jsonb, updated_at=now()
WHERE id='assetmap.delivery' AND value='"legacy"'::jsonb;
```

`requested` 期间，新入库的相关事件开始登记待办。图谱工作者切换时短暂锁住 events 写入，
等待原有写事务结束，补齐旧游标之后的待办（以及最近 24 小时内因慢时钟早于旧游标而尚未物化的最新一条 5001/5020 清单），再原子切换为 `queue`；锁等待上限 5 秒，
整个切换上限 30 秒，失败保留 requested，下轮重试。不要手工跳过 requested 直接设置 queue。

验收应确认 `assetmap.delivery` 为 `"queue"`、待办持续被消费，并补传一条早于旧游标的测试事件，
验证图谱更新及重投不重复计数。仅看服务健康或原始事件入库不能证明图谱消费成功。
现有依赖边与计数保留；**切换前已被旧游标漏掉的历史事件不会自动修复**，不得直接重扫累加，
否则已有计数会重复。

切换后不要直接回滚到不支持待办的旧版本，也不要手工改回 legacy。优先在支持待办的版本上修复；
如确需旧版回滚，应先停止新事件接入，排空接入队列和图谱待办，核对完整物化后另行安排迁移。

### 历史遗漏只读核对

`server/cmd/graphaudit` 用与日常消费相同的连接归一化、入站过滤和进程名称回查逻辑，
在一个 PostgreSQL 只读一致性快照中对比事件、图谱和待办。连接由 `DATABASE_URL` 环境变量提供；
不需要停接入，也不会修改图谱计数。

```bash
# 在 server/ 下执行；先选短窗口，确认负载与差异再扩大
# DATABASE_URL 应通过已有安全环境配置提供，不写进脚本或命令历史
go run ./cmd/graphaudit -since 2026-10-30T05:00:00Z -until 2026-10-30T06:00:00Z
```

大范围核对建议使用备库直连地址并加 `-replica-only`；工具在同一事务中验证 `pg_is_in_recovery()`，
连到主库会直接失败。HAProxy 的主库入口即使在备用节点上，也不等于备库连接。

扫描在同一快照中按小时分段，避免一个稀疏区间拖长单次查询。
窗口为左闭右开；默认最多核对 10 万条事件、总时限 2 分钟，每次数据库查询最多 30 秒。
超限或超时直接失败，不能把部分扫描当作核对完成。`pending` 是快照中尚在待办队列里的记录，
不参与差异统计；`missingLinks` 是窗口内观测到、图谱却没有的边，`belowObservedCount` 是已有累计计数
小于窗口内观测数的边，`examples` 最多列出 50 个差异样本。

窗口内计数只是累计计数的下界：零差异不证明窗口外数据完整，也不能证明累计数没有遗漏。
核对使用资产当前登记的地址及现存进程记录；历史 IP 变更或已过期的进程事件需要另行核实。
此工具只提供修复依据，不自动重放或覆盖历史计数。

### 按保留窗口重建图谱

`server/cmd/graphrebuild` 用保留的原始网络事件重新建立依赖边和计数。必须先完成只读核对，
并确认**全部 server 节点已升级到支持图谱维护锁的版本**；旧工作者不识别维护锁，不能混跑修复。
只能在 `assetmap.delivery=queue` 的主库执行。维护锁暂停图谱消费和清理，原始入库与待办登记继续运行。

```bash
# DATABASE_URL 来自安全环境；since 是明确选择的重建起点
# apply 表示已确认工作者版本以及计数重置范围，不是普通核对命令
go run ./cmd/graphrebuild -apply -since 2026-09-30T07:00:00Z -max-events 2000000 -timeout 10m
```

- 起点包含、终点为取得维护锁后的数据库快照时间；仅重建该范围内仍保留的网络事件。
- **计数重置为所选窗口的可核实观测数**，不延续无法从原始事件证明的历史累计值。窗口外的旧边会移除。
  已过期删除的原始事件无法恢复；历史地址和进程名仍受上述核对限制影响。
- 同一事务将原 `asset_links` 完整保存到工具维护的 `assetmap_rebuilds.previous_links`，记录 ID、窗口、快照时间和扫描量。
  此表不参与图谱消费，也不由事件保留期清理；备份包含原业务地址，按数据库管理员权限保护。
- 现存同键边保留 ID，计数和时间按证据重设。重建与快照内网络待办确认原子提交；库存/软件待办不受影响。
- 快照之后入库的事件，即使事件时间早于快照，仍留在队列；释放锁后由工作者正常消费。失败或超限全部回滚。
- 重复执行会重新计算，不把旧结果累加。完成后核对队列持续消化、图谱缺口、实时入库延迟和数据库复制状态。

不要直接把备份覆盖回正在消费的图谱，否则会丢失重建后新增的计数。需要恢复时，先取得同一维护锁，
核对重建后的新增事件及待办，再制定恢复范围；原图 JSON 用于保留证据，不是自动回滚脚本。


依赖边只记 (源地址, 目的地址, 端口, 协议, 发起进程)，对端是哪台资产在**读取时**按 IP 解析：
发现的机器后来纳管了，图谱自动连上。不算依赖的连接：回环、组播、链路本地、自己连自己，
以及宿主机里容器之间的通信（源地址不是本机登记的地址、目的与源同在一个私网段）。
未指定地址（`0.0.0.0` / `::`）不是节点：agent 的 UDP 出站源地址缺省或未指定时（未 connect 的套接字），
发起方就是上报的资产，记成它登记的与目的同族的地址（私网优先），资产没有可用地址就不记。
旧版本留下的未指定源地址边归属不可信（唯一键里没有资产，多台机器连同一目的会落在同一行），
引擎启动时删掉，活跃连接随新事件按资产地址重新长出来（`engine.go` dropUnspecified）。

UDP 只收端口低于系统临时端口范围的未连接套接字（Linux 读 `ip_local_port_range`，
Windows 按 49152），客户端随机端口不算监听。`/proc/net/*` 只反映 agent 所在网络命名空间：
agent 跑在容器里时看到的是容器自己的监听。

## 区域与暴露级别

区域判定优先级：组管理员手工指派 > 组内网段（最长前缀）> 云元数据 > 按 IP 公私。

| 区域类型 | 含义 |
|---|---|
| `internal` 内网 | 无公网地址的内网主机（CGNAT 100.64/10、IPv6 ULA 也算内网） |
| `dmz` 隔离区 | 组管理员定义的网段 |
| `external` 公网区 | 带公网地址，或组管理员定义的公网网段 |
| `cloud` 云上 | agent 读到了云厂商元数据 |

暴露级别：公网区、带公网 IP、云上有公网地址都算**公网可达**；DMZ 区域算**隔离区可达**；
其余**仅内网**。绑在具体公网地址上的服务直接算公网可达，回环监听不进攻击面。

区域在「攻击面 → 网段与区域」里由组 admin 维护，网段统一规范成网络地址写法；
删除区域时指派到它的资产回到自动划分。

## 攻击面

每台资产的每个（协议, 端口）算一条暴露面，同时绑在 `0.0.0.0` 与 `::` 的双栈监听合成一条；回环监听不算。
风险分 = 暴露级别 × 端口风险 × 重要程度：

| 因子 | 取值 |
|---|---|
| 暴露级别 | 公网 20 / 隔离区 6 / 内网 2 |
| 端口风险 | 高 3（远程管理、数据库、容器编排、文件共享等）/ 中 2 / 低 1，按端口推测，见 `assetmap/ports.go` |
| 重要程度 | AI 标注或人工指定的 1-5，未标注按 3 |

每条暴露面附带观测到的访问来源；来源里出现公网地址标「有公网访问」——这是实际被外部
访问的证据，不是推测。

前端默认以图展示：从左到右是互联网与各区域，每台资产一张卡片、每个对外服务一行，箭头是观测到的
访问路径，直接指向被访问的那一行；「隐藏低危」默认开启（有公网访问的低危服务仍然显示）。
切到列表可按风险分排序。

### 服务说明与调查

端口表认不出的服务通过**服务说明**命名，存在资产的 `service_notes` 上，键为 `协议/端口`，来源有三档，
高的不被低的覆盖：

| 来源 | 怎么来的 | 覆盖规则 |
|---|---|---|
| `ai` AI 识别 | 资产标注时，把端口表认不出、也没有更高结论的对外监听列为 `unknownServices`，模型凭进程名与路径命名 | 只覆盖自己写过的 |
| `investigation` 已调查 | 在服务详情点「调查」，AI 助手上机查证后用 `identify` 工具写回服务名、依据与风险 | 覆盖 AI 识别，不覆盖人工 |
| `human` 人工 | 服务详情里「标注服务」 | 最高；清除后回到 AI 识别或端口推测 |

服务说明的风险（high / medium / low）覆盖按端口推测的风险，进而影响风险分。调查会话里的命令照常受
命令名单与审批约束，提示词要求只读排查。

**盲区**：与本组资产有往来、却没有纳管的内网地址，分两个方向列出：本组连过它的哪些端口、
它访问过本组的哪些服务。其他组的已纳管资产不算盲区，也不露主机名。

还没上报设备清单的资产（旧版 agent 或刚接入）会在攻击面顶部点名：它们的暴露面是空的，
不代表没有暴露。

## AI 标注

模型看到的只是事实：主机名、系统、地址、区域、云环境、监听端口、内网依赖与被依赖、
公网目的地址（个数，以及连接量最多的 30 个连同端口、发起进程与下面的背景信息）、见过的程序。
输出角色、功能说明、重要程度（1-5）、依据、对端关系说明和公网地址用途。
输出不可信：只取第一个 JSON 对象，逐字段校验与截断；关系说明只保留事实里出现过的对端，
公网用途只保留给过的地址，依据不足的地址不写用途。

## 公网目的地址的背景信息

光看 IP 认不出外联的是什么。后台单活任务给公网地址（不含已纳管资产）补背景信息，缓存 `IPINFO_TTL_DAYS`（默认 7）天。
先补最近一周告警里出现的地址（情报命中取自规则 ID，其余取告警对应事件的两端，最近的在前）——情报命中的入站对端
不在依赖边里，只按外联挑永远轮不到；再按连接量从多到少补最近一周连过的地址。只读查询视图 `ip_infos` 同样对组开放
本组外联与本组告警里出现的地址。

- **离线归属库**：本地 mmdb 查 AS 号、AS 组织名与国家，**不向任何外部服务发送地址**，每轮最多 1000 个，
  写在 `ip_infos` 的 `ipdb_asn` / `ipdb_org` / `ipdb_country` / `ipdb_at`，与 VirusTotal 的同类字段分开存、各自到期重查。
  私网、保留与 CGNAT 地址不查。库目录 `IPDB_DIR`（镜像默认 `/opt/openxdr/ipdb`），缺库时这几个字段留空，
  启动日志说明一次；库文件替换后一分钟内自动重新加载，不用重启。数据源与更新方法见下文「离线归属库」
- **反向解析（PTR）**：默认开启，每分钟最多 20 个，`IPINFO_PTR=false` 关闭。查无记录记为空；超时、DNS 服务出错这类临时失败
  不落库，30 分钟后重试（退避只在内存里，换节点从头来）
- **VirusTotal**：配置 `VT_API_KEY` 才查，取归属（AS）、国家、判恶意/可疑的引擎数与历史解析域名；
  按 `VT_PER_MINUTE` / `VT_PER_DAY` 限额（默认免费额度 4 / 500），429 停到下一分钟，key 被拒停一小时。
  **配置后资产连过的、告警里出现的公网 IP 会发给 VirusTotal**

图谱「互联网」节点与资产画像按地址列出外联明细（端口、进程、连接量、最近活动、反查域名、归属、VT 判定与用途）。
归属（组织名、AS 号、国家）VirusTotal 有的用它的，没有的用离线库补；用到离线库数据时明细下方带 DB-IP 署名链接。
AI 研判上下文同样附上告警里出现的公网地址的缓存背景，离线库与 VirusTotal 分开写，不一致时模型能看出来。
用途有两个来源：资产标注时 AI 据上述事实给出的推断，以及上机调查的结论（Pi 的 `egress` 工具写回，来源 investigation，
优先显示，不覆盖人工结论）。认不出的地址在明细里可以一键交给 AI 上机调查。

VirusTotal 判恶意的引擎数达到 `VT_ALERT_MIN_ENGINES`（默认 3，控制台可改，0 关闭）时，地址加入威胁情报（来源 virustotal，
随缓存期到期），之后再有主机连它就按情报命中出告警；重查后不再达到阈值的立即失效，人工录入的同一地址不受影响。

触发时机：

- **入库**：新资产的设备清单到了就标注（清单迟迟不到，最多等 10 分钟后凭已有事实标注）
- **变动**：每 10 分钟重算一次事实指纹（监听端口、内网依赖、区域、云环境），变了就重标，
  同一台至少间隔 1 小时；程序清单与公网目的地址变化频繁，不进指纹
- **定时**：超过 `ASSET_ANNOTATE_REFRESH_HOURS`（默认 24）没标过的重标，0 表示只在变化时标
- **人工**：资产画像里点「重新标注」

标注调用关掉 GLM 模板里的隐式思考（与 Pi 会话同一判定），输出上限 2048 token：隐式思考不返回却占输出，
实测同一台主机耗时在 17 秒到超过 120 秒之间波动，后台批量调用会反复超时。

人工改过的角色、功能说明、重要程度记入 `locked_fields`，AI 不再覆盖；「交还 AI」解锁并立即
重新标注。每轮最多标 3 台；失败的资产 10 分钟内不再重试。未配置 `AI_MODEL` 时不做标注，
图谱与攻击面照常可用。

AI 助手的对话上下文里，组内资产清单也带上了角色、重要程度、区域和暴露级别。

### 离线归属库

数据源选 [DB-IP Lite](https://db-ip.com/db/lite.php)（IP to ASN Lite + IP to Country Lite，mmdb 格式）：

- **许可**：[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，可随产品再分发、可商用，条件是署名。
  控制台展示了离线库数据的地方带「IP Geolocation by DB-IP」链接到 https://db-ip.com；库目录里的 `NOTICE`
  （更新命令写入）随文件一起分发。自行转载查询结果（报告、导出）时同样要保留署名
- **没选的**：MaxMind GeoLite2 需要账号并接受 EULA，不能随产品分发（同结构的 `GeoLite2-ASN` / `GeoLite2-Country`
  由用户自己下载、改成下面的文件名放进目录也能用，许可由使用者负责）；iptoasn.com（PDDL）的国家是 AS 注册地而非
  地址所在地，且只有「最新」一个版本，二者都不如 DB-IP Lite 合适
- **国家的含义**：`ipdb_country` 是地理定位得到的 ISO 3166 两位代码，任播、云厂商地址可能和 AS 注册地不一致；
  归属只说明是谁的网络，不说明善恶

目录里放两个文件：`dbip-asn-lite.mmdb` 与 `dbip-country-lite.mmdb`，各约 10MB，各自可缺。打开时核对 metadata 的库类型，
两份放反不会加载。

**分发方式**：发版的 server 镜像自带一份（release.yml 在构建前用更新命令下载当月库、校验后经 `--build-context ipdb=` 注入，
哈希记在发版日志和镜像里的 `SHA256SUMS`；下载或校验失败发版直接失败）。DB-IP 每月更新、只保留最近两个月且不发布校验和，
固定版本加 SHA256 的写法过一两个月就会因为原文件下架而构建失败，所以不在 Dockerfile 里下载：本地与离线环境的 `docker build`
不联网取库，得到的镜像库目录为空，server 照常运行，只是归属字段留空，启动日志会说明。

**更新**：镜像里带 `openxdr-ipdb` 命令（源码 `server/cmd/ipdb`）。它只下载公开的整库文件、不发送任何要查的地址；
两份都下完并通过结构校验、库类型核对与探测地址检查才原子替换，失败不动原有文件。不给 `-month` 取当月，月初未发布退回上月。

```bash
# 镜像内目录归 root，不能原地更新：挂一个可写目录并指向它
#   volumes: ["./ipdb:/ipdb"]   environment: { IPDB_DIR: /ipdb }
docker compose run --rm --no-deps --entrypoint openxdr-ipdb server -dir /ipdb
# 离线环境：在能联网的机器上 go run ./cmd/ipdb -dir <目录>，再把两个 .mmdb 拷过去（先拷成临时名再 mv，不要原地覆盖）
```

server 每轮检查文件的修改时间与大小，变了就重新打开，一分钟内生效；已有记录按 `IPINFO_TTL_DAYS` 到期后用新库重查。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/asset-map?groupId=` | 组 viewer | 节点（本组资产 / 未纳管地址 / 别组资产 / 互联网）与有向边；`groupId=all` 是全部组视图，仅全局管理员，所有组的资产都画成主机节点、跨组连接连成主机到主机，资产节点带 `groupId` |
| GET | `/api/attack-surface?groupId=` | 组 viewer | 汇总、暴露面（按风险分降序）、盲区 |
| GET | `/api/zones?groupId=` | 组 viewer | 区域定义 |
| POST | `/api/zones` | 组 admin | `{groupId,name,kind,cidrs}`；同名 409 |
| PUT / DELETE | `/api/zones/{id}` | 组 admin | 修改 / 删除 |
| GET | `/api/assets/{id}/profile` | 组 viewer | 资产画像：区域、暴露、云、监听、依赖、标注 |
| PUT | `/api/assets/{id}/profile` | 组 analyst | `{role?,summary?,criticality?,unlock?:[]}`，改即锁定 |
| PUT | `/api/assets/{id}/zone` | 组 admin | `{zoneId}`，null 回到自动划分；只能指派本组区域 |
| POST | `/api/assets/{id}/annotate` | 组 analyst | 请求重新标注；未配置模型返回 503 |
| PUT | `/api/assets/{id}/services` | 组 analyst | `{port,name,note?,risk?}` 人工标注服务；`name` 为空表示清除。只接受资产上真实存在的监听 |

`/api/attack-surface` 另带 `peers`（访问方节点）与 `paths`（访问方 → 资产的某个服务，含连接数），供攻击面图使用；
暴露面条目的 `note` 是生效的服务说明。

区域增删改、标注修改、区域指派都写审计日志。

## 配置

| 位置 | 项 | 默认 | 说明 |
|---|---|---|---|
| server 环境变量 | `ASSET_ANNOTATE_REFRESH_HOURS` | `24` | 定时重新标注周期，0 只在变化时标注 |
| server 环境变量 | `AI_MODEL` 等 | — | 与旧 triage 共用模型配置 |
| server 环境变量 | `IPDB_DIR` | 空（镜像内 `/opt/openxdr/ipdb`） | 离线 IP 归属库目录，见上文「离线归属库」 |
| 主机采集配置 | `collectInventory` | `true` | 关掉后该主机不上报监听端口与云环境 |

## 已知限制

- Linux agent 只有 eBPF 构建才上报出站连接；netlink / 轮询模式下依赖边只能来自 sensor
- 端口到服务的映射是推测，不做协议识别
- 「公网可达」按地址与区域判定，没有从外部实际探测可达性
- 云元数据探测只在 agent 启动时做一次；实例更换公网地址需要重启 agent 才会更新
- Windows 监听表与云探测只经过交叉编译与单元测试，尚未实机验证
