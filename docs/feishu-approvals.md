# 飞书私聊命令审批

飞书应用机器人为进入既有人工审批队列的命令发送私聊卡片，审批人可以点击批准或拒绝。
它不改变命令名单、AI 审计员、硬拒绝清单和响应开关；批准仍由原有命令闸门消费，执行结果以平台命令回执为准。
实现位于 `server/internal/feishuapproval/`，控制台入口是“审批 → 飞书私聊审批”。

## 配置与绑定

1. 在飞书开放平台创建企业自建应用，启用机器人，将审批人纳入应用可用范围。
2. 开通 `im:message:send_as_bot` 和 `im:message.p2p_msg:readonly` 权限。
3. 在“事件与回调”的事件配置及回调配置中均选择长连接，分别添加 `im.message.receive_v1` 和 `card.action.trigger`，保存并发布生效。
4. 确认服务已配置持久的 `HOST_CREDENTIAL_KEY`。全局管理员在上述控制台入口填写 App ID、App Secret 并启用。密钥加密存储，不向浏览器回显。
5. 每位审批人登录自己的平台账号，生成绑定码，十分钟内将完整绑定码私发给机器人。不要转交他人或发送到群。
6. 点击“私发测试卡片”，再点击收到的卡片中的验证按钮。此测试只验证身份和回调，不执行主机命令。

服务器需要出站 HTTPS/WSS 连接飞书；无需新增公网回调端口。配置了飞书调用 IP 白名单时，加入服务器实际出口 IP。
同一集群由数据库租约选出的单个服务节点维护连接；其他节点页面显示的是各自进程的连接状态，不能单凭非主节点状态判断整体断线。

## 通知与安全边界

- 只给已绑定且当前有对应组审批权限的管理员投递卡片。点击时重新校验应用、租户、操作人、原始消息、随机标识、配置版本、账号权限和审批有效期。
- 绑定码只保存哈希且只能消费一次；解绑撤销旧码与旧卡片。保存应用配置会使旧卡片失效，已有申请可在平台处理。
- 同一申请只能决定和消费一次；拒绝、过期或无权限的请求不能下发命令。卡片不直接访问主机执行接口。
- 命令超过 4000 字符或含不适合展示的控制字符时，不展示直接审批按钮，须到平台核对完整命令。
- 启用飞书审批后，命令审批通知不再重复发送到原 Webhook。未绑定、离线或发送失败也不会回退到群机器人；请在平台处理待审批项。普通告警和报告保留原通知渠道。
- 停用或尚未配置此功能时，命令审批仍使用原通知器。读取配置失败时不会将命令内容发送到备用渠道。
- 绑定码到期清理，投递记录在过期 30 天后清理；审批及安全审计保留原有策略。

## 接口与排查

所有接口沿用平台会话认证。`GET /api/approvals/feishu` 返回配置摘要、本人绑定和验证状态；
`PUT /api/settings/feishu-approval` 仅限全局管理员；
`POST /api/approvals/feishu/bind`、`DELETE /api/approvals/feishu/bind` 仅操作本人绑定；
`POST /api/approvals/feishu/test` 每人每分钟最多申请一次测试卡片。

长连接正常但收不到消息时，检查应用发布版本、本人可用范围和事件订阅；能收到卡片却不能点击时，检查回调配置标签中的 `card.action.trigger`。
毫秒和微秒两种回调时间戳均执行相同的新鲜度检查；过期、转发或更换配置前生成的卡片须回到平台处理。
日志不输出 SDK 原始事件、长连接 URL、密钥或命令；全局管理员可查看有限的时间戳和布尔诊断状态。
