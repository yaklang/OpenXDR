# 多模型自动切换

在「设置 → AI 模型」保留研判主模型与助手主模型，点击「获取 API 模型列表」，再按优先级选择备用模型并保存。列表接口使用表单当前的 API 地址和密钥，不必先保存密钥。上游不支持 `/models` 时，可以直接输入模型标识。

当前服务的备用列表最多 8 个，留空关闭同服务模型切换。下方「备用 API 服务」可再添加最多 4 套服务，各自配置名称、API 地址、加密密钥、研判模型、助手模型及最多 3 个备用模型。先尝试当前服务，再按备用服务的显示顺序尝试。服务可启停、上移、下移或移除；用途模型留空则该服务不承接此用途。没有配置任何备用服务时保持原来的行为。

启用备用服务表示管理员允许把任务对话、工具结果与数据发送到该地址。只添加公司批准的服务，内网源码任务必须使用公司内网地址。模型目录只表示上游公布的模型，不证明账号权限、工具调用能力或上下文长度。获取目录使用该服务当前表单的地址与独立密钥；已保存的密钥留空不改，点击清空并保存才删除。

切换用于事件研判、资产标注等平台文本调用、抑制草案评审，以及 AI 助手和定时任务。已有图片请求保持指定模型，不自动切到文本模型。主模型为空时仍表示相应功能未启用。

- HTTP 402：尝试下一个模型，失败模型冷却 15 分钟。
- HTTP 429：尝试下一个模型，冷却 5 分钟。
- HTTP 500 / 502 / 503 / 504：尝试下一个模型，冷却 1 分钟。
- 配有其他服务时，HTTP 401 / 403 跳过本服务剩余模型，冷却该服务 5 分钟；连接异常跳过本服务，冷却 1 分钟。密钥随服务整组替换，不把原服务的密钥或认证头转交下一套服务。
- 其他 HTTP 错误、取消、无效 JSON 或无效结果：直接报错，不盲目换模型。没有跨服务配置时，连接或认证错误仍直接报错。

每次请求按主模型、同服务备用模型、后续备用服务的顺序尝试，并按地址、凭据与模型去重，最多 25 个。全部冷却或失败会明确报错；冷却结束后重新从主模型开始尝试，不永久修改主模型。Go 调用的冷却按节点、端点、密钥摘要与模型隔离；Pi 冷却在单轮运行进程内保留，下一次运行会重新尝试主模型。冷却不持久化、不跨节点共享。

流式调用仅在成功响应建立前切换，收到成功响应后流中断不切换；不会重新运行整个 Agent，也不会因切换重新执行已完成的工具。新模型沿用完整的消息和工具结果历史，原有人工审批、组权限与高危命令闸门继续生效。成功消息及用量记录使用实际调用的模型；会话设置仍显示配置的主模型。连接测试始终只测试所选主模型，以免备用成功掩盖主模型故障。

`POST /api/settings/ai/models` 和其他 AI 设置接口一样只允许管理员调用，返回最多 1000 个去重模型标识，响应限制为 1 MiB、超时 15 秒，不携带密钥返回，也不跟随重定向。可传 `providerId` 获取指定备用服务的目录。设置字段 `fallbackModels` 是逗号分隔的有序模型标识字符串，可用 `reset: ["fallbackModels"]` 清空回默认。`providers` 是有序的备用服务数组，传空数组删除全部备用服务，不传则保留；密钥按服务 ID 分别加密绑定，解密失败停用该服务，不用匿名身份调用。

验证：在 server/ 执行 go build ./...、go vet ./...、go test ./...；使用独立测试 PostgreSQL 执行 INTEGRATION_DATABASE_URL=... go test -tags integration -p 1 ./...。在 server/pi-runtime/ 执行 npm ci 和 npm test；在 web/ 执行 npm ci、npm run build、npm run lint。模型调用测试使用本地模拟服务，不需要真实模型密钥。

平台 Pi 与沙箱的 `model-fallback.mjs` 保持相同；Pi 单测检查两份文件一致，更新时必须同步。沙箱镜像须随功能重新构建，旧镜像不会识别新配置。沙箱防火墙也需由管理员放行所配置的备用服务；此功能不会自动扩大网络权限。
