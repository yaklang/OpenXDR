# OpenXDR 与 DYGK 独立欺骗引擎接入

状态：运行逻辑抽离和统一接入已实现；本地核心验证通过，Linux CI 和容器镜像构建尚待执行。未发布、未部署。日期：2026-10-27。

启动方式沿用 OpenXDR 主编排和同一份 `.env`。平台自动识别引擎版本，按组授权的部署修订下发配置、分配实例和签发身份。引擎产物独立发布，运维无需为每个登记维护一套连接器参数。操作步骤见 [独立欺骗引擎运行包](../integrations/dygk/README.md)。

## 1 实现边界

| 组成 | 负责 | 源码 |
| --- | --- | --- |
| 原生运行引擎 | SSH、HTTP 兼容模板、Linux 文件监视、有限模拟 Shell | `server/deception/native`、`sshdecoy`、`runner` |
| DYGK Web 引擎 | HTML 隐藏入口、有界归档、模拟凭据验证、局部封禁和假后台 | 锁定上游源码，由 `integrations/dygk/web` 接入 |
| 契约与 SDK | 版本、模板元数据、事实白名单、平台认证与租约 | `server/deception/contract`、`sdk` |
| 平台控制面 | 资产、组授权、部署修订、内部实例分配、审计、观察、复核和研判 | `server/internal/api/deception*.go` 与现有 `decoy*.go` |
| 控制台 | 同一诱饵页管理运行模式、停止、版本和历史配置 | `web/src/pages/DecoysPage.tsx`、`components/DeceptionEngine.tsx` |

原生代码沿用仓库 Go module，独立构建二进制；没有本地 `replace` 或额外工作区。Web 引擎在 Node 24 独立镜像运行，不改变 Pi 的运行环境。平台 server 不加载原生诱饵运行包，只引用契约及受限 SDK。

DYGK 基线从最初评估的 `4780099` 更新到 `bd8515a0b930f530eec0d13955fe502d8c8e9e25`。新基线已经将有界假后台并入正式库。DYGK 源码可从本地导出目录或远端仓库获得，统一由锁文件记录版本与内容摘要，再由构建脚本生成适配后的运行副本；原生运行实现集中在 `server/deception/`，后续更新不再向 `server/internal` 复制模板或会话代码。

当前是构建时源码集成。`integrations/dygk/` 内纳入版本管理的是接入代码、脚本、测试及锁文件；默认本地输入 `local-source/`、远端 checkout `.downloads/` 和适配缓存 `.upstream/` 均被 Git 忽略，新克隆的仓库不携带私有源码。Docker 保留本地输入、排除开发缓存，最终镜像只保留运行核心及接入实现。源码来源由同一 `.env` 的 `DYGK_SOURCE=local|remote` 选择，默认本地、不自动回退，来源目录由 `DYGK_LOCAL_SOURCE` 配置。云端本地模式需要独立提供源码，配置不会引用开发机路径。详见 [源码来源配置](../integrations/dygk/README.md#源码来源配置)。

## 3 统一启动和内部控制

每个引擎发布版本最多调度 100 个有效托管登记。数据库先按当前发布版本及 `hosted=true` 筛选，再检查容量；其他版本和非托管登记不占这个额度。超过上限返回 422，不截断任务列表，以免管理器误停未返回的实例。

```text
OpenXDR 同一 .env 和主 docker compose
                 |
       server 与 deception 服务
                 |
   受限 Unix socket，未开放网络管理端口
                 |
   平台分配登记、修订、实例及短期身份
                 |
        DYGK 托管站点与本地状态卷
                 |
   白名单观察 → 复核事件 → 现有 AI 研判
```

通过 `COMPOSE_PROFILES=dygk` 启用服务，继续使用主 `docker compose up -d`。独立镜像版本由同一配置的 `DYGK_VERSION` 选择。默认关闭 profile，不影响原有部署。

控制卷只挂给 server 和引擎，目录 0700、socket 0600，两者使用同一受控 UID。Kubernetes 等环境须初始化控制卷的属主权限，不能只设置一个可写的任意共享目录；分离到不同节点时使用高级远端运行协议和受信 HTTPS。

内部控制面自动登记实际运行版本并保存心跳，不会重新启用已被全局管理员停用的版本。调度只处理组管理员明确选择平台托管的 HTTP 诱饵；原生文件、SSH 和 Shell 不会被移到平台主机上冒充远端采集。

实例分配持有资产锁，写运行身份、租约和审计后才交给引擎。已有有效租约不重复分配；资产迁组后停止旧实例，不自动向新组重签。内部退出确认绑定登记、实例、修订和产物，允许受控引擎在旧令牌失效后确认本地实例已关闭，不接收任何旧组事件内容。

## 4 部署数据与版本化协议

`DecoyEngineRelease` 保存引擎、版本、摘要、协议、状态格式和准入状态；`DecoyRevision` 保存不可变修订和配置。登记引用当前修订，运行令牌另外绑定签发时的组及修订。历史观察保留其原修订，不以新模板解释旧证据。

现阶段能力由已测试的版本化契约固定列出。载体、内容策略、接入方式和动作模式分开校验；`decoy/pause/padding` 不直接等同 `observe/block/quarantine`。未知字段、未知事实和不支持的动作组合拒绝。

保留旧 `/api/decoy-runtime/{id}/config|lease|events`，兼容现有安装。新运行端使用 `/api/deception-runtime/v1/deployments/{id}/`：

| 接口 | 作用 |
| --- | --- |
| `POST handshake` | 精确产物、实例和修订握手，领取 starting 租约 |
| `GET config` | 获取登记、已授权配置和停止请求 |
| `POST lease` | 合法状态转换与续租，绑定实例、修订和令牌代次 |
| `POST observations` | 每批 1–100 条白名单事实，按稳定 ID 逐条确认持久化 |

高级远端运行包使用 HTTPS 和单登记 Bearer 令牌。托管运行包通过私有 socket 使用同一运行 handler，身份由平台内部签发，不要求运维填写。客户端不能在事实中声称平台资产、组、进程或指令来源。

令牌过期、撤销、迁组、修订不符及版本停用均拒绝后续运行认证。旧接口不接受已启用修订的登记，防止协议降级。租约只表示运行端进行了回报，不是主机远程证明或外部可达性证明。

## 5 事实与复核

事实只含稳定 ID、流代次、序号、发生时间、计数、不透明会话标识和受支持类型。平台另记接收时间及可信登记、修订、实例；相同 ID 不同内容返回冲突。

| 引擎事实 | 平台处理 |
| --- | --- |
| 入口、归档、验证页 | 有界访问轨迹，不直接确认攻击 |
| 模拟凭据验证成功 | 同一修订、会话和触发类型只创建一次复核事件 |
| 局部封禁、假后台启动及后续请求 | 记录已执行的本地动作事实，与主机隔离分开 |
| 导出缺口 | 保存缺口事实，不宣称轨迹完整 |

原生标记仍保留原有单次使用和代次边界，不把 DYGK 的多会话验证改名塞进旧 `marker_used`。平台事实不携带来源 IP、Cookie、真实或模拟凭据、任意请求体、原始会话 ID或自报模型身份。来源仍只能定性为未确认。

继续使用 `source=decoy` 和 `decoy.observation.*` 告警前缀，复用现有复核、incident、审计、通知排除与自动响应限制。仅有诱饵观察不能自动隔离主机；AI 判良性也不代替人工复核。Pi 避让清单继续覆盖这些登记及历史登记。

## 6 上游扩展与可靠交付

上游本来只有同步 `onEvent` 回调和最近事件快照。连接器显式应用受摘要保护的扩展，增加持久 UUID、流序号和增量读取；回调只做通知，导出日志作为补传依据。表单状态和触发事实、封禁状态和封禁事实分别同事务提交，避免状态已推进却没有事实。

事件与导出日志同 SQLite 事务写入。连接器本地持久保存待发送事实，得到平台确认后删除；网络超时沿用原 ID，平台数据库幂等消重，采用至少一次交付。流清空换代、保留淘汰与容量缺口显式记录，不承诺无限离线保留。

假后台的来源 TTL、请求预算和已揭示入口持久保存；重启不重新发放预算。源码适配位置、事件类型和文件摘要均在构建时校验；上游新增未知事实时停止候选更新，不能静默降级。

停止先关闭入口，再有界补传并回报最终状态。旧修订有未确认积压时禁止转报新修订。平台临时失联时，独立诱饵停止，业务网关停止生成诱饵并透传既定 upstream，原动作保留到其原 TTL。托管版本被明确停用时停止实例；操作前应安排业务入口流量。

## 7 更新与回退

锁文件保存快照版本、来源仓库、包版本、许可、协议和文件摘要；远端来源另外要求完整 commit，本地来源允许无 Git 历史的源码导出和按内容生成的快照版本。构建产物的实际摘要写入 `engine-manifest.json`，运行端自行核验。两种来源都接受相同的适配和兼容检查，包内不含弱密码示例、研究执行器、宿主目录或临时 checkout 依赖。

候选更新验证源码、适配位置、事件契约、上游行为和连接器；平台兼容检查继续验证真实运行闭环。兼容更新只需发布独立运行包，新增参数、事实或权限仍需适配契约及准入。

部署换版先停止旧实例，在同一 `.env` 更新引擎镜像版本，再选择匹配的不可变修订。历史配置恢复也创建新修订，必须匹配实际产物。状态格式不兼容时拒绝原地换版，需要新登记和明确迁移；升级前保留存储快照，不将回退镜像等同回退数据库。

## 8 验收与发布边界

本地已验证原生引擎与 SDK 单测、新协议和托管分配集成、真实 Node 引擎到 PostgreSQL 复核闭环、跨组与迁组、去重、停止、原有诱饵自动响应限制，以及 Web 类型检查、构建和 lint。Go 全包 Linux 交叉构建和静态检查通过。

Linux CI 还会验证受限 socket 下托管进程自动启动、完整上游测试和独立 Docker 镜像。当前本机没有 Docker，尚未执行镜像构建；Windows 完整测试存在符号链接权限、SQLite 清理和部分测试程序执行限制。全量集成发现的事件分区迁移游标问题已在未修改的基线复现，不属于此次诱饵改动。

OpenXDR 原生代码保留 Apache 2.0 来源；DYGK 当前为 `UNLICENSED`，公开分发需确认授权。独立镜像发布工作流保留显式仓库开关，当前未发布、未部署。
