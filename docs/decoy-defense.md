# 三层诱饵防御：策略来源与接入边界

运行实现已抽离至独立引擎，统一接入与云端部署见 [运行包说明](../integrations/dygk/README.md)。

最新平台实现见 [多载体诱饵](multi-carrier-decoys.md)：已扩展统一登记、HTTP/HTML、Linux 文件打开监视、模拟 Shell 与认证事件回传。下文 SSH 实验证据保持原适用范围。

当前开发分支为 `ssh-decoy`，工作区 `/home/Kei/OpenXDR-decoy`。这里提供独立 SSH 诱饵、固定策略目录和受控实验，不自动修改真实 SSH 或启动生产服务。

## 三层分别选择

| 策略 | CLI | 固定模板 | 已有证据 | 不能据此声称 |
| --- | --- | --- | --- | --- |
| 诱饵识别 | `-profile decoy` | `identify-v1` | 同一诱饵的有效标记可关联发放与使用会话 | 确认是 AI、恶意攻击或同一主体 |
| 暂停注入 | `-profile pause` | `operator-close-v1` | 第十轮闭合组 3/3 暂停；未闭合完整样本 0/2，另一次超时 | 跨模型普遍有效，或服务端能直接观测对方暂停 |
| 输出填充 | `-profile padding` | `padding-8k-v1` | 固定 8192 字节、无注入或标记指令，握手与输出边界已验证 | 已证明独立填充会稳定拖延、耗尽 token 或打穿上下文 |

运行时一次只选一个策略。`profile` 和原始实验 `template` 互斥，未知名称和组合字符串直接拒绝。运行策略最多输出 8192 字节；32 KiB 等历史模板只能通过显式实验模板入口选择，不能覆盖策略限制。

没有同时勾选三层的接口。历史实验已观察到工具截断会使尾部指令不可见，因此需要分别评估，再决定是否设计组合策略。填充使用固定原创文本，不生成随机乱码、不无限输出、不引入睡眠或无限交互。

`padding-8k-v1` 与第八轮的 `novel-8k-v1` 不同：后者在小说后附带注入指令，前者只有填充正文。第八轮观察到的工具输出截断是历史线索，不能当作新纯填充模板已经完成模型验收。

## 可运行部分

```sh
cd server
go build -o /tmp/openxdr-sshdecoy ./cmd/sshdecoy
/tmp/openxdr-sshdecoy -list-profiles
```

目录仅输出策略 ID、显示名称、层次、模板 ID 和证据说明，不输出污染正文。`-list-profiles` 不读取私钥、不创建事件文件、不启动监听，可供后续管理端展示。

按 [独立服务启动说明](ssh-decoy.md) 提供专用主机密钥、全新事件文件和布放标签，以 `-profile decoy`、`pause` 或 `padding` 选择策略。没有传 profile/template 时，CLI 默认使用 `decoy`；显式 `-template deter-v1` 可复现旧默认。原实验脚本显式传入模板，入口仍保留。

所有策略都保持：独立端口、认证全部拒绝、无 shell/exec/转发、不主动回连、事件不保存来访身份/密码/源地址、每实例 16 个并发连接、每连接 10 秒、最多 3 次密码失败。事件持久化失败或达到文件大小上限即停止服务。

## 事件只记录可观察事实

所有策略事件携带 `profile` 和确切 `template`；显式历史模板模式省略 `profile`，避免伪装成已选择的运行策略。客户端用户名中的任何所谓 profile/role 信息都不能覆盖它们。

事件继续只包含 Banner 准备、密码认证、标记使用/拒绝等事实，`attribution` 固定为 `unconfirmed`。没有 `model_paused`、`ai_confirmed` 或 `tokens_consumed` 之类服务端无法证实的事件。没有后续连接可能是代理停止、连接中断或工具不显示 Banner，不能自动判为防御成功。

最终的“暂停成功”和“输出截断”来自靶场的模型回答、执行器动作及工具轨迹核验，并非线上 SSH 服务能独立产生的结论。

## 控制台登记

资产菜单的「诱饵管理」页按当前组显示登记，组管理员（全局角色至少 analyst）或全局管理员可登记和撤销。只能选择三种内置策略；模板版本由服务端确定，不接受自定义正文或模板覆盖。

- `GET /api/ssh-decoy-profiles`：登录后查询策略元数据，不返回模板正文。
- `GET /api/ssh-decoys?groupId=<uuid>&offset=0`：每页最多 50 条，返回 `{items, more}`。
- `POST /api/ssh-decoys`：`{assetId, profile, port}`；资产必须已分组。
- `POST /api/ssh-decoys/<id>/revoke`：幂等撤销登记，保留历史记录。

登记保存到 `decoy_deployments`，状态只有 `registered` / `revoked`。同一资产端口最多一条未撤销登记；撤销后允许重新登记。创建与首次撤销均在同一数据库事务写入审计。授权跟随资产当前归组，迁组后原组不再能管理这条记录。登记期间锁住资产行，避免与迁组交叉执行。

**登记不会启动服务；统一 decoyhost 会在授权核验失败后停止，旧独立 sshdecoy 仍需手动停止。端口是否空闲、远程运行状态均未核验。** 页面不会把登记数当成已布放或防御成功数。记录 ID 可作为独立服务的本地布放标签，但不是服务端签发的授权凭据；原 sshdecoy 本地实验入口不上传事件；统一 decoyhost 的 SSH 和其他载体使用独立认证接口，见多载体文档。

## 验证

`go test -race ./deception/sshdecoy ./cmd/sshdecoy` 验证真实握手拒绝认证、标记关联、三种策略的输出边界、策略与模板冲突拒绝、不可变目录副本及事件归属；还保留原有容量、重放、隐私与持久化失败测试。

实验结论主要参见 [第八轮长度边界](ssh-decoy-evaluation-round8.md) 和 [第十轮同期复测](ssh-decoy-evaluation-round10.md)。源码新增策略后与历史冻结指纹不同，历史复测脚本拒绝当前版本是预期行为；复现历史实验需恢复对应版本，不应删除指纹校验。

登记接口的集成测试覆盖组权限、迁组、重复端口、并发登记、幂等撤销和审计；需使用独立测试库执行 `go test -tags integration -p 1 ./internal/api -run TestSSHDecoy`。
