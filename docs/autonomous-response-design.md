# 自主响应与自身防护设计

起因同 [跨主机攻击的关联与升级设计](attack-campaign-design.md)。2026-11-02 跳板开始喷洒，11-03 打进生产库，
11-03 10:11 每日巡检已经把入侵写成「紧急」，但推送暂停，三天没人处置。攻击方是自动化的，几小时写了十几个脚本，
比人工响应快得多。

结论有两条：

- 平台要自己闭环。人在事后审计、推翻决定，不在关键路径上。通知还要发，但内容是「已经做了什么」，不是「请来处理」。
- 能自主动手的平台本身就是最值钱的目标，自身防护和自主响应要一起设计。

## 现状

| 项 | 现状 | 问题 |
|---|---|---|
| 开关 | 生产只开了 `RESPONSE_ENABLED`，`AUTO_RESPONSE_ENABLED` 没开 | 实际上没有自主响应 |
| 触发 | 只有 AI 研判结论 malicious 且置信度 ≥ 90（`response/auto.go`） | 分钟级；模型不可用时完全不响应 |
| 动作 | 只有隔离整台主机 | agent 支持 9 种处置，自动响应只用了最重的一种 |
| 目标 | incident 里所有涉事资产，**包括受害者** | 这次如果开着，会隔离 node1，自己把生产停掉 |
| 粒度 | 主机 | 攻击者在 uos-server 的靶场容器里，隔离主机会把整个平台一起断掉 |
| 界面 | incident 详情里的 `ResponsePanel` | 看不到平台做过什么、什么还在生效，也没有集中撤销 |
| 指令通道 | agent 执行收到的任何指令；跨节点经 NATS，6222 只靠一个共享密码 | 拿到路由密码就能给全网发 root 命令（已由指令签名修复，见下文） |

## 设计

### 一、两条触发路径

**快路径：确定性信号，秒级，不经过模型。** 告警落库后同步判定，命中就进入处置引擎：

| 信号 | 依据 | 现状 |
|---|---|---|
| 内网横向喷洒 | `xdr:internal-lateral-spray`（P0 已上线） | 有 |
| 数据库进程拉起 shell | postgres / mysqld / redis-server / sqlservr 的子进程是 sh / bash / python 等（`COPY FROM PROGRAM`、UDF） | 有（`lnx_database_spawns_shell.yml`，2026-11-04） |
| 容器逃逸 | 容器里 nsenter / unshare / 经 /proc/1/root 跳进宿主机命名空间（`lnx_container_namespace_escape`），或改写、探查 cgroup release_agent（`falco/release_agent_container_escape`）。只隔离那个容器；核心资产记跳过 | 有（2026-11-09；回测：uos-server 靶场失陷 7 次真阳性，node1 patroni 容器里的运维操作落在核心资产上跳过） |
| 反弹 shell | shell、解释器或 netcat 类工具的标准输入输出被 dup 成一条 TCP 连接（`lnx_shell_stdio_to_network`，依赖 agent 的 stdio_socket 事件）。结束该进程、本机封锁对端（对端是本机自己的地址时 agent 拒绝封锁，只结束进程）；核心资产只告警 | 有（2026-11-09；回测：上线 12 小时除 sshd 外没有进程这样做，sshd 不在名单里） |
| 爆破得手 | `xdr:bruteforce-success` | 有 |
| 高置信情报命中 | 情报库 C2 / 恶意 IP 的出站连接 | 有 |

信号清单写在代码里，不由 AI 或配置临时扩充；新增信号要像新规则一样回测误报。

**慢路径：AI 研判。** 保留现有的 malicious ≥ 90 钩子，但目标选择和动作强度改走下面同一套引擎，不再直接隔离全部涉事主机。

### 二、按角色选目标

这是这次最大的教训：**遏制攻击来源，对受害者只做外科手术式的处置。**

| 角色 | 怎么认 | 处置 |
|---|---|---|
| 来源主机 | `lateral_evidence` 的 `src_asset`；受害方事件里 `authfields.PeerIP` 落在纳管主机上 | 按区域等级遏制（见下） |
| 来源容器 | 来源主机在窗口内连向受害地址的出站网络事件，取事件的 `container` | 隔离这个容器，不动宿主机 |
| 受害主机 | 告警所在资产 | 结束恶意进程树（如 postgres 下的 sh），封锁来源地址；**永远不隔离整机** |

来源容器能认出来，是因为 agent 的 eBPF 网络采集带进程与容器归属：跳板容器的流量在受害方看来源地址是宿主机 IP（Docker NAT），
但宿主机上的 agent 看得到是哪个容器发起的。

### 三、动作强度按区域等级

在区域（`Zone`）上加一个处置等级字段（`response_tier`），资产可以单独覆盖（`PUT /api/assets/{id}/response-tier`）。未指定时为「生产」：

| 等级 | 适用 | 来源侧 | 受害侧 |
|---|---|---|---|
| 实验 | 靶场、CTF、AI 实验机、测试 VM | 隔离容器；认不出容器就隔离主机 | 结束进程 + 封锁来源 |
| 生产 | 默认 | 隔离容器；认不出容器就封锁它与其他纳管主机的通信，不隔离主机 | 结束进程 + 封锁来源 |
| 核心 | OpenXDR 自身节点、数据库、网关、DNS | 只封锁来源，不隔离 | 只结束确认恶意的进程、封锁来源 |

运行 OpenXDR server 的资产自动归入核心，不依赖人工配置。

### 四、遏制租约

每次自动处置都是一条**租约**，记在新表 `containments` 里：

- 字段：资产、动作、目标（容器 ID / 地址 / 进程）、触发信号、关联 incident、下发的指令、生效时间、到期时间、状态、解除人与原因。
- 默认有效期 24 小时。同一来源在租约期内又有新证据，就自动续期。
- 到期前由 AI 复核：攻击是否还在继续、来源是否已清理干净。复核结论只能是「解除」或「续期」，**不会自动升级成更重的动作**。
  复核出错按续期处理。
- 人可以随时解除，解除会下发反向指令并记审计。

到期自动解除只适用于封锁和容器隔离。结束进程不可逆，只记录，不进租约。

### 五、新能力：容器隔离

agent 新增 `ISOLATE_CONTAINER` / `UNISOLATE_CONTAINER`，目标是容器 ID：

- Linux：按 cgroup 找到容器里的进程，进它的网络命名空间（`/proc/<pid>/ns/net`），在里面建一张独立的 nftables 表，丢弃全部流量。
  宿主机和其他容器都不受影响。
- 只支持 docker / containerd / LXC 这类有独立网络命名空间的容器。`network_mode: host` 的容器拒绝执行并说明原因。
- 容器重启会换网络命名空间，隔离随之失效。租约期内 agent 检测到同一容器 ID 重新出现时，自动重新隔离并回报。

### 六、保险丝

- **熔断**：一小时内全局自动处置超过 N 次（默认 10），或单组超过纳管主机数的 20%，就停止自动处置，只记录待执行的决定，
  等组管理员恢复。宁可漏处置，也不能让一个误报信号把全网关掉。
- **幂等**：同一信号、同一目标只处置一次，ID 由信号与目标派生（沿用 `auto-isolate` 的做法）。
- **全程审计**：动了、没动、被熔断挡住，都要写清「为什么」。
- **指令签名**：见下文。签名是自主响应的前提，否则就是在给攻击者造武器。

### 七、页面：自主响应

控制台新增一级菜单「自主响应」：

- **当前遏制**：生效中的租约、剩余时间、触发证据，可以一键解除。
- **决策记录**：每次判定的时间线，包括被跳过和被熔断的，点进去能看到信号、角色认定和选择的动作。
- **策略**：信号 × 等级 → 动作的矩阵。第一版只读，展示代码里的策略。
- **熔断状态**：当前计数与阈值，组管理员可以在这里恢复。

通知改成事后报告：「已自动隔离 uos-server 上的容器 range_c11_comp1_t2，原因是 60 分钟内对 6 台主机喷洒 SSH」。

## 自身防护

### 已完成：端到端指令签名（PR #32）

- 每条指令都装进签名信封：绑定目标 agent、一小时有效，用 `COMMAND_SIGNING_KEY_FILE` 的 Ed25519 私钥签名。
- agent 首次注册时固定公钥，只执行验签通过的信封里的指令。
- 数据库、跨节点 NATS 或单条投递链路被人摸到，都伪造不出 agent 肯执行的指令。

剩下的缺口：server 节点本身被拿下时，节点上有私钥，也能通过自动升级分发安装包。后者要用离线密钥给安装包签名，单列一项。

### 待做

1. **控制面网络收口进部署代码**：5432 / 8008 / 2379 / 6222 只对固定的对端开放，写进 `deploy/ha`，替代 11-04 手工加的
   KEI-DBGUARD / KEI-ETCDGUARD。PR #31 一并处理。
2. **把 OpenXDR 自身当核心资产监控**：数据库进程拉起 shell、pg_hba 或 Patroni 配置被改、陌生地址访问 etcd、
   告警表或审计表被批量删除、核心节点 agent 掉线，都走快路径。
3. **审计防篡改**：审计做成哈希链，定期把链尾写到集群外的见证节点（jumpbox）。删记录能被发现。
4. **安装包签名**：自动升级只接受离线私钥签过的安装包，与指令签名分开两把钥匙。

## P1 实现说明

代码在 `server/internal/containment`，单活循环每 5 秒一轮（`CONTAINMENT_*` 配置见 [部署文档](deployment.md)）。
开关与范围在「自主响应」页由全局 admin 改，存 settings 表、每轮读取；`CONTAINMENT_ENABLED` / `CONTAINMENT_SCOPE` 设了就锁定。
关闭只停新的处置，已生效的租约照常对账、到期复核或解除。
平台指令与已知自动化引起的告警不处置。例外是数据库拉起 shell、反弹 shell、容器逃逸：运维不会这样做，出现在可信来源（登记过的运维钥匙、来源网段）上说明钥匙或来源已经失守，照样处置。

### 信号与处置

| 信号 | 处置 |
|---|---|
| `xdr:internal-lateral-spray` | 来源是实验等级就隔离来源主机；受害方封锁实际看到的来源地址（`lateral_evidence.src_ip`，不用资产登记的地址，里面有 docker 网桥这类不能封的）。来源与受害方都是核心时不封 |
| 数据库进程拉起 shell（`rules/lnx_database_spawns_shell.yml`） | 结束该进程；从 PostgreSQL 后端的进程标题取出发起命令的客户端地址，在数据库主机上封锁（核心资产也封）；客户端是纳管主机时按喷洒同样的办法遏制来源 |
| `xdr:bruteforce-success` | 受害方封锁登录来源、锁定被攻破的账号（内置账号由目标校验挡下，核心主机不锁）；来源地址唯一属于某台实验等级的纳管主机就隔离它 |
| 情报命中 IP（级别 ≥ 4） | 封锁该地址；本机主动外连这个地址时结束发起连接的进程。入站命中只封锁：被命中的是本机的服务进程，结束它就是自己制造故障 |
| 情报命中域名（级别 ≥ 4） | 只封锁；DNS 归属可能落在本机的解析服务上，不结束进程 |
| 情报命中文件哈希（级别 ≥ 4） | 进程本身的文件哈希命中就结束进程；隔离该文件（核心资产不隔离文件）。哈希碰在父进程等别的字段上不处置 |

封锁与隔离主机是租约，到期自动解除。结束进程、隔离文件、锁定账号一次性执行（`executed`），**不自动恢复**：
把被爆破的账号自动解锁、把恶意文件自动放回，都比不恢复更危险，恢复由人做。

### 处置等级

- **优先级**：运行 `openxdr-server` 的资产（按监听清单）一律核心 > 人工指定（锁定）> 区域指定（`zones.response_tier`，可为空）> AI 定级 > 默认生产。
- **AI 定级**：并在资产标注里。模型同时给出 `responseTier` 与依据，写进 `assets.response_tier` / `response_tier_reason`；人改过的锁定，AI 不再覆盖。
  模型判的重要程度高于 2 却给实验等级时，两个判断矛盾，按生产处理。认不出的也按生产。
- **伪造核心**：监听清单是 agent 自己报的，失陷主机能伪造成核心。但核心只让它自己免于隔离，受害方照样封锁它。

### 租约、范围与熔断

- **租约**：键是「资产 + 动作 + 目标」，同一个键同时只有一条 active。新证据把到期时间推到最后一条证据之后 `TTL`。
  同一条告警已经为某个键做过决定（包括被跳过、被熔断），就不再重新决定。
- **到期**：直接下发解除，不做 AI 复核（P4 再加）。解除下发失败（agent 离线）就推迟 5 分钟重试，租约保持生效。
- **范围**：`CONTAINMENT_SCOPE=lab` 时，攻击涉及的主机（来源、受害方或失陷主机）里没有实验等级的就只记 skipped。
- **熔断**：按滑动窗口数生效过的处置，挡下的记 held，不会补执行。手动恢复等 P3 的页面。
- **受保护目标**：目标都经 `response.NormalizeTarget` 校验，`ISOLATION_ALLOW` 里的 server 地址不封、内置账号不锁。
  未配置 `ISOLATION_ALLOW` 时不隔离。

## P3 实现说明

- **页面**：控制台「运营 → 自主响应」，展示四块：
  - 开关、范围与熔断状态；
  - 决策记录（可按状态筛选）；
  - 人工解除或恢复；
  - 策略矩阵。
- **人工解除**（`containment.Lift`）：下发恢复动作，送达才把状态记为 lifted。
  - 解除时间之前的证据不再触发同一处置，包括同一批证据里晚到的另一条告警（11-04 生产验证时踩过）；之后的新证据照样触发。
  - 结束进程撤不回。
- **熔断计数**：人工解除的也算，它们当时确实生效过。
- **通知改成事后报告**：还没做，等飞书推送恢复后接上。

## P2 实现说明

- **agent**：新增 `ISOLATE_CONTAINER` / `UNISOLATE_CONTAINER`（`agent/src/respond/container.rs`），目标是容器 ID。
  - 扫 `/proc`，按 cgroup 找到容器里的任一进程，在临时线程里 `setns` 进它的网络命名空间执行 nft：
    建独立表 `openxdr_container_isolation`，除回环外进出全部丢弃，已建立的连接一并切断。
  - 网络命名空间与宿主机（pid 1）相同的容器拒绝执行，那等于隔离宿主机。
  - 仅 Linux。容器重启会换网络命名空间，隔离随之失效。
- **来源容器认定**：在来源主机上找窗口内连向受害主机地址的外连事件（agent 按 cgroup 标了 `container`），取发起的容器，QEMU 不算。
  - 喷洒窗口同 `SprayWindow`；爆破得手往前看 10 分钟。
  - 容器流量出宿主机时经过 NAT，受害方只看得到宿主机地址，必须靠宿主机上的 agent 认。
- **处置**：容器隔离走租约，到期自动解除，人工可解除。
  - 实验与生产等级认出容器就只隔离容器。
  - 实验等级认不出容器才隔离整机，生产等级认不出就不动来源，核心不动来源。
- **已知局限**：2026-11-02 那次，uos-server 的 agent 没有报出跳板容器连向受害主机的外连（受害方的探针看到了），
  回放语料里也没有这类事件，所以回放验收仍是隔离整机。其他 docker 主机的容器外连现在都带容器归属。

## 数据库拉起 shell（2026-11-04）

11-03 入侵时，`COPY FROM PROGRAM` 拉起的 sh 在事件里父进程只剩 PID。PostgreSQL 后端是 postmaster fork 出来、不 exec 的，
agent 的进程注册表里没有它。按父进程判断的规则对这类攻击全部落空。

- **agent**：启动事件的父进程不在注册表里时，现场读 `/proc/<ppid>` 补名字、路径与命令行（`live_parent`，原来只用于折叠）。
  PostgreSQL 后端的进程标题带着客户端地址，例如 `postgres: postgres openxdr 10.1.1.170(41866) COPY`。
- **规则**：`rules/lnx_database_spawns_shell.yml` 判定数据库服务进程（postgres / mysqld / mariadbd / redis-server / mongod / sqlservr）
  拉起 shell、解释器或下载工具，排除 PostgreSQL 启动时的 `locale -a`。
  - 语料用 11-03 生产原文，加 MySQL UDF 变体与 `locale -a` 良性对照。
  - 生产近 3 天，数据库父进程的子进程只有 2 条 `locale -a`。
- **快路径**：结束该进程、在数据库主机上封锁客户端地址，客户端是纳管主机就遏制来源。
  按 11-03 原样，客户端 uos-server 是实验等级，范围 `lab` 下也会处置。

## P4：到期 AI 复核（2026-11-05）

- **复核内容**：租约到期时，配了模型（用量记作 `containment`）就把这条处置交给 AI。只给计数与摘要，不给告警原文：
  - 处置本身；
  - 租约期间两边主机上 3 级及以上的告警；
  - 来源最近 24 小时的喷洒证据数；
  - 被隔离容器最近一小时是否还有活动。
- **结论只能二选一**：解除（下发恢复动作）或续期（再续一个 `TTL`），依据写进决策记录与审计。
  输出认不出、模型出错都按续期，一小时后再问。
- **兜底**：没配模型时到期直接解除（P1 行为）。租约满 7 天不再问模型直接解除，模型一直说续期也不能把主机永远封着。

  - **封存**：单活任务每 5 秒把新审计按 (ts, id) 编号，`seal = HMAC(前一条 seal ‖ 本条全部字段)`。

  - **校验**：每 10 分钟全量校验，编号不连续或 seal 对不上就出 `xdr:audit-tamper`（5 级，同一处一天一次）。

  - **代价**：写入路径不变，封存是事后补上的；刚写入还没封存的几秒内改动发现不了。没配签名私钥的部署不启用。
