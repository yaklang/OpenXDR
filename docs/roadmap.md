# 路线图

原则先行：**解决真实存在的问题，不为臆想的需求写代码。**
每一项都要回答"谁会因为没有它而受伤"。回答不了的，进"不做"清单。

## 现状快照（2026-08）

- **采集**：Linux 进程（eBPF/netlink/轮询三级降级 + exe SHA-256）、敏感文件
  （inotify）；Windows 进程（ETW）；全流量探针（DNS/TLS/HTTP 元数据 + JA3）；syslog
- **检测**：Sigma 引擎（热重载）16 条规则、四类 IOC 情报碰撞
- **降噪**：去重 → 抑制 → 关联（血缘/时间窗/横向移动）→ AI 研判 → 通知阈值
- **响应**：结束进程、主机隔离（mTLS + 按主机绑定证书）
- **运营**：概览漏斗、事件检索、规则/情报/抑制/资产/审计页、三角色 RBAC

## P0 —— 下一步就做

**1. Windows 采集对称性。**
Linux 有敏感文件监控，Windows 没有——而勒索与持久化的主战场恰恰是 Windows。
注册表持久化点（Run 键、服务、计划任务）+ 敏感目录监控，ETW 或
ReadDirectoryChangesW。谁受伤：一半以上的真实客户资产在 Windows 上裸奔。

**2. 登录事件采集。**
账号是第二攻击面，目前登录可见性完全依赖 syslog 转发。Linux 读 wtmp/btmp 或
PAM，Windows 订阅 ETW Logon。有了它才有"爆破成功"（N 次失败后一次成功）、
异常时段/源地址登录这类账号维度检测——现在的 ssh 失败规则只看得到失败，
看不到最关键的那次成功。

**3. 事件检索的规模化。**
`raw::text ILIKE` 在千万行表上会全表扫。pg_trgm GIN 索引是十行改动，
大规模部署前必须有。顺带评估 events 表按时间分区（原生分区即可，
TimescaleDB 作为可选增强）。谁受伤：第一个日活跃事件过百万的用户。

**4. 检测面对拍验证。**
拿 Atomic Red Team 在测试机上跑一遍，量化"16 条规则到底能抓住多少常见技战术"，
缺口直接变成新规则清单。检测产品不做对拍，覆盖率就是自我感觉。

## P1 —— 看得见的价值

**5. MITRE ATT&CK 映射。** 规则打 technique 标签（Sigma 本身有 tags 字段，
引擎目前丢弃了），前端出覆盖矩阵。运营一眼看清"我们防住了哪几列"。

**6. incident 报告导出。** 一键 Markdown：判定、攻击链、时间线、告警明细、
处置记录。分析师写汇报的时间不该花在复制粘贴上。

**7. AI 研判升级为工具调用。** 现在是把截断的 500 字事件塞进 prompt；
让 LLM 能主动查"这个进程的父链""这台主机最近的外连"，研判质量上一个台阶。
误报反馈（分析师标记 false_positive 的案例）回流进上下文。

**8. agent 配置下发。** 监控目录、采集开关目前编译期写死。复用现有指令通道
下发配置，不需要新协议。

## P2 —— 时机到了再做

- **agent 独立网络采集**（无 sensor 的小部署盲区；eBPF tcp_connect 采样）
- **UEBA 雏形**：新进程首次出现、外连基线偏离。克制：先做"首次出现"这一种，
  它的信噪比最高
- **自动响应**：高置信度 malicious 自动隔离。必须默认 dry-run + 白名单 +
  审计，误杀一台生产机的代价高于慢五分钟
- **macOS agent**（Endpoint Security Framework）

## 不做

- **多租户 / SaaS 化**——目标用户是自建 SOC 的团队，租户隔离用"每客户一套"解决。
  为不存在的 SaaS 生意把每张表加 tenant_id，是给所有查询上税。
- **微服务拆分 / server 水平扩展**——单机 Go + Postgres 能撑到远超目标规模；
  dedup/correlate 状态外置换来的是分布式债。垂直扩容 + 读写分离足够。
- **存 PCAP 全包**——磁盘无底洞，会话元数据 + 按需取证是行业共识。
- **自研规则 DSL**——Sigma 生态就是护城河，兼容它而不是发明方言。

## 工程债（随手清）

- sensor 侧尚无 JA3S / 服务端指纹
- Windows ETW 采集无文件哈希（进程事件里补 exe SHA-256 需处理镜像路径转换）
- 前端无移动端适配（SOC 大屏优先，低优）
