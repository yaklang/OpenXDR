- 12 次生成均获得答案：自动通过 7 次；工程复核 7 项 pass、2 项 fail、3 项 needs_review。

- summary 的 failed_checks=9 是未通过条目数，不等于模型事实错误数量。

## 复核发现

1. incomplete_query / 2：把“无工单”扩写为“无人工确认记录”，并建议放宽 limit、避免正文裁剪，违反工具能力。可选 evidence_claims 被省略。
2. mixed_clients / 1：把“未提供人工授权”扩写为“没有人工授权记录”。
3. 待核：incomplete_query / 1 的“换用 process_guid 查询”（原工具本来已按 GUID）；confirmed_attack / 1 的“暂存打包”超出单纯写入文件的明确描述；confirmed_attack / 2 建议使用尚未提供的程序哈希，须明确先获取并与暂存文件哈希 H1 区分。
4. 新增 raw 取消裁剪、血缘时间参数两个错误能力反例均正确识别；但同一泛化补证建议在不同校准中获得不一致的独立建议评分。正对照“已说明截断/超时”和生成中的“保留记录”还被要求重复固定限制句。需修正评分边界，不能通过反复重跑挑选通过结果。
