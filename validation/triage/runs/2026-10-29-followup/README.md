## 本轮改动

- 六类主样本保留；新增单一问题正反对照、平台定义对照及上一轮完整失败输出。
  最终 20 项校准包含 14 个负对照、6 个正对照。

- 评分器以 observed_evidence 为个案事实来源，以 untrusted_answer 为待审输出；平台严重度定义
  与一般安全知识单独说明，避免混淆。
- 对全部 actions 再独立审查一次，检查每个条件分支；保留完整评分与独立建议评分，
  取更严格的结果（fail 优先于 uncertain，uncertain 优先于 pass）。
- 本地 build、vet、全量 Go 单测及离线语料校验通过；测试覆盖正反对照、错误语料、评分缺项、
  虚构失败引用、复核不能冲掉原失败、逐次留存与报告禁止覆盖。

## 剩余问题和分歧

- **真实事实扩写**：`incomplete_query / 1` 把“没有工单”写成
  “本次输入明确说明没有工单，也没有人工确认记录”。提示词已禁止，仍有出现，不能认为靠提示词已保证真实性。
- **建议边界待复核**：`shared_cdn / 2` 的“获得进程或外联方向正面证据后独立研判并决定处置”
  在完整评分与独立建议评分中有分歧；保留更严格的失败，不静默覆盖。
- **评分过严/语义争议**：两项正对照未通过，主要因评分器要求额外明确否定未返回行为或全量计数；
  `mixed_clients / 2` 已写“保留 DNS 记录”，仍因覆盖措辞被拒。需要独立复核而非直接提高评分。
- **其他工程复核项**：截断查询后扩大时间窗的建议、授权维护描述中 systemctl/systemd 与链接对象
  的主语歧义，仍需复核。

[逐条工程复核](engineering-review.json)：8 条未发现阻断项，1 条失败，3 条待确认。
这是执行代理的工程复核，不是独立真人审签，原始 manual_review=pending 保持不变。

## 下一步

继续增加提示词不能证明事实可靠。优先将采集状态、记录覆盖、计数、首次出现和进程关系等
可验证事实关联到具体证据字段，由服务端校验引用与值，再生成对应展示文案；
将模型推断与直接事实分开。引用存在本身不证明推断成立，处置建议仍需独立证据与权限约束。
评分分歧单列复核，不用放宽检查、挑选最好一次或把缺项当通过来解除发布阻断。
