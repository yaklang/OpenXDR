# 2026-10-29 研判回归首轮

**结论：回归工具可用，候选提示词质量验收未通过，不部署。**

本轮使用生产配置中读取的 `deepseek-flash` 端点与模型调用脱敏证据快照；不读取业务事件、
不注册调查工具、不执行响应或通知。模型与评分器使用同一模型，评分不能替代独立人工审签。
`deepseek-flash` 是端点返回/配置的模型标识，供应商内部不可变版本未知。

基于 `9b90178` 的未提交工作区；各版本完整提示词和评分提示词保存在本目录，摘要与 JSONL
metadata 已核对。旧语料为 `cases-v1.json`，v2 使用 [v2 语料快照](cases-v2.json)。

## 已复现的问题

- 原提示词 `no-thinking / mixed_clients / 2`：建议“若核实为未知应用或发现隧道/信标行为”就隔离，
  评分器错误放行；v2 的负对照已包含这种分支，实测评分器明确拒绝。
- `v1 / mixed_clients / 2`：仍建议出现高频查询、长应答或外联就“立即升级为 malicious 处置”，
  自动评分错误放行；v2 加强了所有条件分支的证据门槛。
- `v2 / ai_memory / 2`、`mixed_clients / 2`：把“证据未提供/没有记录”升级成“未采集”，
  输入没有明确采集状态字段；前者建议中还保留了进程异常等单一条件通往处置的问题。
- `v2 / confirmed_attack / 1`：把“陌生落地二进制”扩写为“首次出现的可执行文件”，
  输入没有历史基线或首次出现时间。
- `v2 / ai_memory / 1` 的条件性处置与 `authorized_maintenance / 2` 的进程箭头关系仍需独立确认。

逐条记录见 [engineering-review.json](engineering-review.json)。工程复核由执行代理完成，
不是独立真人审签；原始报告的 `manual_review=pending` 保持不变。自动评分通过不能解除发布阻断。

## 下一步
